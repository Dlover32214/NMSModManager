## 1. 总体结论

对方不是做了一次小修补，而是把数据模型和主界面重构成：

```text
全局模组库（Pool）
  └─ 配置（Profile，多套有序清单）
       └─ 当前配置里的模组（Mods，主列表 / 加载顺序）
```

并围绕这个模型增加了：

- 多配置切换、复制、重命名、删除；
- 内置「无模组」配置，替代原来的「启动原版 / 启动 Mod 版」双按钮；
- 独立的模组库页面、批量加入/移出；
- 模组链接字段与打开/编辑链接；
- 模组格式/健康检查；
- 路径安全、JSON 损坏保护、日志轮转、单实例；
- 拖拽浮起预览、延迟忙碌遮罩等交互改进；
- 新的构建脚本、CI、docs、CONTRIBUTING。

原项目里的 `VanillaLaunchStore` / `vanilla-launch.json` / 双启动按钮被对方**移除**，由「无模组」配置取代。这是本次合并中最大的行为变化。

## 3. 模组、配置与模组库

### 3.1 新的 `library.json` 模型

`LibraryState` 升级为 `SchemaVersion = 3`：

```text
Mods             全局模组库（所有记录）
Profiles         配置列表（每套一份有序 Entries）
ActiveProfileId  当前配置 Id
```

- `ModProfile`：`Id` / `Name` / `Entries` / `UpdatedAt` / `Deletable` / 兼容字段 `LegacyEnabledIds`。
- `ConfigEntry`：`ModId` + `Enabled`，顺序即加载顺序。
- 内置 `ModProfile.NoneId`（「无模组」）：空清单、不可改名/删除、不写入 `library.json`。
- 当前配置的启停状态是唯一真相：`SetActiveProfile` 会把配置状态“投影”到 `ModRecord.Enabled`，不在配置里的模组一律停用。

### 3.2 旧数据迁移

对方专门处理了从旧版“只有一份启停状态”升级的场景：

- 如果旧库没有 `Profiles`、但存在已启用模组，会自动生成一套名为「默认」的配置；
- 旧库里的 `Enabled` 状态被迁进这套配置，避免升级后所有模组都掉进模组库、部署时被整体停用；
- 旧配置里的 `LegacyEnabledIds` 会迁移到 `Entries`，然后清空；
- 指向已删除模组的条目会被 `PruneMissingEntries()` 清掉；
- 旧版 `library.json` 的 `FolderName` / `LibraryPath` / `DeployName` / `PakFiles` 继续兼容读写。

### 3.3 配置操作

`ModLibrary` 从 159 行扩展到 559 行，新增：

- `MenuProfiles`：内置「无模组」永远排第一；
- `ActiveProfile` / `ActiveMods` / `PoolMods`；
- `SetActiveProfile`：切换并同步启停；
- `CreateProfile(name, copyActive)`：默认复制当前清单；
- `RenameProfile` / `RemoveProfile`；
- `RefreshDeletable`：只剩一套配置时不能删；
- `AddToActiveProfile` / `RemoveFromActiveProfile`；
- `MoveEntry` / `MoveEntriesToEdge`；
- `MissingProfileEntries` / `NextProfileName`。

界面行为：

- 新建配置默认复制当前配置；
- 删除配置只删清单，模组和文件不动；
- 删除当前配置时自动切到剩余第一套，没有则切「无模组」；
- 在「无模组」配置下不能加模组，必须新建一套配置。

### 3.4 模组库页面（Pool）

- 主列表只显示当前配置；池页面显示全库。
- 导入的模组自动加入当前配置。
- 不在当前配置里的模组留在模组库，文件停在 `MODS_disabled`。
- 支持从池里批量加入当前配置、批量移出。
- 外部模组面板可以逐条或全部收编。
- 新增 `ModPickerWindow`，用于从池里勾选模组加入当前配置。

### 3.5 移出语义

- 「移出配置」：先从配置摘掉，再把记录停用；文件保留。
- 「移出模组库」：从全局库删除记录并停用，文件仍保留在 `MODS_disabled`。
- 「永久删除」：二次确认后删除 `MODS` / `MODS_disabled` 中的文件。

## 4. 启动逻辑的变化

### 4.1 原来的双启动被移除

原项目：

- `VanillaLaunchStore.cs` / `vanilla-launch.json`；
- 左下角「启动原版」「启动 Mod 版」两个按钮；
- 启动原版前记录启用状态，下次启动 Mod 版恢复。

对方版本：

- 删除 `VanillaLaunchStore.cs`；
- 只保留一个 `LaunchCommand`；
- 「无模组」配置就是原版启动；
- 启动前先 `DeployAsync`，同步失败或 `report.Failed > 0` 时不启动；
- 根据全库是否有启用模组或外部模组，写 `DISABLEMODS.TXT`；
- 不再需要 `vanilla-launch.json`。

### 4.2 影响

- 老用户如果依赖“启动原版后自动恢复上次启用状态”，现在需要改用配置：把原版状态放进「无模组」或单独一套配置。
- 这是功能替代，不是简单删除；但确实是行为不兼容点。

## 5. 模组健康检查与格式识别

`ModInspector` 在旧版已经存在，对方主要把它接进了列表和池的 UI，并扩展了展示。

新增/强化的检查：

- 统计 `EXML` / `MBIN` / `.pak` / `MXML` / `lua` / 文件总数；
- 判断格式类型：补丁（EXML）、替换（MBIN）、混合、旧式 `.pak`、无有效文件；

- 结合 `VersionParser` 给出游戏版本适配状态。

`ModItemViewModel` 增加 `FormatText`、`WarningText`、`CompatText`、`IsHealthReady`，列表可显示格式、警告和适配状态。

## 7. 部署与路径安全

`DeploymentService` 从 471 行增加到 555 行，核心变化：

- 同步前先 `PathGuard.IndexEntries` 枚举 `MODS` 和 `MODS_disabled`，后续只认真实存在的目录/文件，不再用用户输入拼路径；
- `PathGuard.IsSafeSegment` 拒绝包含路径分隔符、非法字符、`.` / `..` 等目录名；
- 文件夹和 pak 的移动/删除都走索引查找，避免 `Path.Combine` 拼出目录穿越；
- `FileOps` 的 JSON 写入改为显式 `FileStream` + `Flush(true)`（fsync）后再替换，降低断电留下 0 字节文件的概率；
- `DeleteFiles` 同时清理 `MODS` 与 `MODS_disabled` 中真实存在的副本，而不是盲删拼接路径。

新增 `PathGuard.cs`、`TextLimit.cs`：

- `PathGuard`：安全段校验、按磁盘枚举查找、批量索引；
- `TextLimit`：按“字”（Unicode 文本元素）截断，避免把 emoji 代理对或组合字符劈开。

## 8. 日志、单实例与稳定性

### 8.1 日志目录

`AppPaths` 从：

```text
<data>\app.log
<data>\crash.log
```

改为：

```text
<data>\logs\latest.log
<data>\logs\crash.log
<data>\logs\yyyy-MM-dd-HHmmss.log.gz
```

- `AppLog.StartSession()` 每次启动把旧 `latest.log` 压缩归档，只保留最近 5 份；
- 侧栏「日志」按钮打开 `logs` 目录。

### 8.2 单实例

`App.xaml.cs` 新增 `Mutex`：

- 用 `SHA256(程序目录)` 生成稳定名字，避免 `string.GetHashCode()` 每进程随机化导致失效；
- `Local\` 前缀，不跨会话；
- 第二个实例弹窗提示后退出，防止两个进程同时改 `library.json` 和 `MODS`。

### 8.3 损坏保护

- `JsonStore.TryLoad` 区分“文件不存在”和“文件存在但解析失败”；
- `ModLibrary.Load` 遇到损坏时先备份为 `backup_library_yyyyMMddHHmmss.json.bak`，进入 `_corrupt` 状态；
- 损坏保护期间 `Save()` 返回 false，不覆盖原文件；
- UI 明确提示，用户确认后才解除。

## 13. 需要知道的风险 / 取舍

1. **双启动不兼容**：原 `vanilla-launch.json` 和两个启动按钮已移除，改由「无模组」配置实现原版启动。
2. **没有随版本发布自动化测试**：对方删掉了自检工程；本次只用临时探针验证了配置/迁移/损坏保护，未恢复完整 117 项自检。

4. **`mapping.json` 未被代码引用**：目前只是嵌入资源，未发现 `Mapping` 读取点；后续要么接上，要么删除。
5. **SDK 10 单文件发布限制**：必须用 8.0.x 发布；`build.ps1` 已自动处理，手动发布需注意。
6. **配置语义变化**：切换配置会把不在配置里的模组全部停用；这是设计行为，不是 bug。
7. **旧 `tests` / `tools`**：已移到 `.tmp`，不再参与解决方案；需要时可从备份恢复。
